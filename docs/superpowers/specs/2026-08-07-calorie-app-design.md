# 毎日のカロリー計算アプリ 設計書

日付: 2026-08-07

## 背景・目的

以前 Google AI Studio で作成し「カロリー計算」という名前でスマートフォンにインストール済みの
アプリ(NutriFlow AI)と同等の中核機能を、Claude Code で新規に再実装する。
元アプリはクラウド同期・AIカメラ・AIアドバイス・家族管理・グラフレポート等を含む大規模な
アプリだったため、まずは食事記録とカロリー計算の中核機能に絞った MVP を作り、
将来的に段階拡張することを前提とする。

参考にした元アプリの機能一覧(実機URLをブラウザで確認して調査):
- 食事記録(朝食/昼食/夕食/間食・その他 + 水分摂取量)
- 一行自然文入力からのAI推定(Gemini API)
- 料理写真からのAI画像解析(AIカメラ)
- 栄養目標ダッシュボード(エネルギー・PFC・塩分・水分・野菜・果物)
- 月別グラフ・体脂肪換算・PDFレポート出力
- AI管理栄養士によるアドバイス
- Googleログインによるクラウド同期・家族プロフィール管理

## スコープ(MVP)

### 含める機能
- 食事記録(朝食/昼食/夕食/間食の4区分、手動入力)
- ローカル食品データベースに基づくカロリー・PFC・塩分の自動計算(グラム数入力→比例計算)
- ユーザーによる食品の追加登録・編集
- 栄養目標ダッシュボード(カロリー・タンパク質・脂質・糖質・塩分の5項目、進捗バー表示)
- 目標値のユーザー設定画面
- 日付ナビゲーション(前日/翌日、過去記録の閲覧)

### 含めない機能(将来拡張)
- AIによる一行自然文からの栄養価推定(Gemini API等の外部AI連携)
- AIカメラによる写真解析
- AI管理栄養士によるアドバイス
- グラフ・月別レポート・PDF出力
- クラウド同期・Googleログイン・家族プロフィール管理
- 水分摂取量・野菜/果物摂取量の記録

## 技術方針

- **形態**: ビルド不要の静的PWA(`index.html` / `style.css` / `app.js` / `manifest.json` / `sw.js`)。
  「スマホアプリ作成とGitHub自動保存」スキルのPWA実装パターンを踏襲するが、
  今回はGitHub自動保存を使わずローカル保存のみで完結させる。
- **保存先**: ブラウザの IndexedDB。ネットワーク送信は一切行わない。
- **配置場所**: `Git/カロリー計算アプリ/` に独立したgitリポジトリとして作成。
- **意匠**: 実装前に `frontend-design` スキルを呼び、配色・タイポグラフィ・signature要素を検討する。

## データモデル(IndexedDB)

```
foods (食品マスタ)
  - id
  - name: 食品名
  - category: 任意の分類(主食/主菜/副菜/飲料など)
  - per100g: { kcal, protein, fat, carb, salt }  ※100gあたりの栄養価
  - source: "mext" | "custom"  ※文科省データか自分で追加したものかを区別

meals (食事記録)
  - id
  - date: "YYYY-MM-DD"
  - mealType: "breakfast" | "lunch" | "dinner" | "snack"
  - foodId: foodsへの参照(登録済み食品の場合)
  - freeText: 食品未登録時の自由記述(任意、foodIdが無い場合に使用)
  - amountGrams: 入力されたグラム数
  - kcal / protein / fat / carb / salt: amountGramsとfoods.per100gから算出した計算済み値(キャッシュ)

goals (栄養目標・設定)
  - kcal, protein, fat, carb, salt の目標値(ユーザーが設定画面で変更可能)
```

## 食品データベースの初期データ

文部科学省「日本食品標準成分表」を元に、一般的な家庭料理・食材を中心に数百品目程度を
抜粋してJSON化し、`foods.json` として同梱する。初回起動時にIndexedDBへ流し込む。
全収載品目(2000品目超)は検索性・保守性が落ちるため対象外とする。

## 画面構成

| 画面 | 内容 |
|---|---|
| ホーム(ダッシュボード) | 当日の日付表示＋前日/翌日ナビゲーション。カロリー・PFC・塩分の目標比を進捗バーで表示。朝食/昼食/夕食/間食の4区分ごとに記録済み品目リストと小計を表示 |
| 食事記録入力 | 各区分の「＋追加」から開くフォーム。食品名をインクリメンタル検索→候補選択→グラム数入力→カロリー等を自動計算してプレビュー→保存。ヒットしない場合は「新しい食品として登録」導線を表示 |
| 食品登録/編集 | 食品名・100gあたりのカロリー・PFC・塩分を入力して`foods`に追加。既存食品の編集・削除もここで行う |
| 設定 | 1日の目標値(カロリー・PFC・塩分)を入力・保存 |

## 主要な操作フロー(例: 食事を記録する)

1. ホーム画面で「朝食に追加」をタップ
2. 食品名を入力(例:「白米」)→インクリメンタル検索で候補表示
3. 候補から選択 → グラム数入力欄が表示(デフォルト100g)
4. 入力量に応じてカロリー・PFC・塩分がリアルタイムでプレビュー計算される
5. 「保存」でIndexedDBに記録 → ホーム画面のダッシュボードが即座に更新される

## エラーハンドリング・データ整合性

- 食品データが1件もヒットしない検索 → 「見つかりません。新規登録しますか？」を明示
- グラム数が未入力・0以下 → 保存ボタンを無効化(バリデーション)
- IndexedDBが利用不可(プライベートブラウジング等) → 起動時に検知し、保存できない旨を画面上部に警告表示

## テスト方針

手動確認を中心とする(PWAのUI操作が主体のため)。計算ロジック(グラムからの栄養価計算・
目標比の割合計算)のみ、素のJavaScriptによるアサーションベースの軽量な単体テストを用意し、
丸め誤差や0除算などのエッジケースを検証する。

# 日本食品標準成分表の取り込みと食品登録フローの刷新 設計書

日付: 2026-08-08

## 背景・目的

現状、食品マスタは手作業で抜粋した60品目の `data/foods.json` を初回起動時に
IndexedDB へシードしている。品目が少なく、実際の食事を記録しようとすると
目当ての食品が見つからないことが多い。

そこで、文部科学省「日本食品標準成分表(八訂)増補2023年」の全2,539品目を
公式データから取り込み、そこから自分がよく食べるものだけを選んで登録する方式に切り替える。

方針の要点は「**成分表は参照用の辞書、食品一覧は自分専用の短いリスト**」という分離である。
2,539品目すべてを食事記録のプルダウンに出すと選びづらいため、
食品一覧は白紙から始め、ユーザーが成分表から選んで登録したものだけを候補とする。

## スコープ

### 含める機能

- 文科省成分表xlsxから、アプリ用JSONとObsidian閲覧用Markdownを生成する変換スクリプト
- 食品一覧の初期状態を白紙にする(既存のシード食品は自動削除)
- 食品管理画面から成分表を検索し、選んだ品目の栄養値をフォームに流し込んで登録する導線
- 登録時に食品名を編集できること(成分表の正式名称は長く、実用には短縮が必要)

### 含めない機能

- 成分表の全成分(ビタミン・ミネラル等)のアプリ内表示。取り込むのはエネルギー・
  たんぱく質・脂質・糖質・食塩相当量の5項目に限る
- 食品群を階層でたどる専用ブラウザ画面(検索で十分と判断)
- 成分表データの自動更新(文科省の改訂時はスクリプトを再実行する運用とする)

## データソース

- 出典: 文部科学省「日本食品標準成分表(八訂)増補2023年」第2章(データ)
- URL: https://www.mext.go.jp/content/20260327-mxt_kagsei-mext-000029402_02.xlsx
- 一覧ページ: https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html
- 形式: xlsx 約1.9MB、シート「表全体」に全2,539品目、18食品群

### xlsxの構造

| 行 | 内容 |
|---|---|
| 1〜11行目 | 見出し(複数行にまたがる結合セル) |
| 12行目 | 成分識別子(`ENERC_KCAL`, `PROT-` など) |
| 13行目以降 | データ(2,539品目) |

使用する列(0始まりの列インデックス):

| 列 | 成分識別子 | 意味 |
|---|---|---|
| 0 | — | 食品群コード("01"〜"18") |
| 1 | — | 食品番号(例 "01088") |
| 3 | — | 食品名 |
| 6 | `ENERC_KCAL` | エネルギー(kcal) |
| 9 | `PROT-` | たんぱく質(g) |
| 12 | `FAT-` | 脂質(g) |
| 18 | `FIB-` | 食物繊維総量(g) |
| 20 | `CHOCDF-` | 炭水化物(g) |
| 60 | `NACL_EQ` | 食塩相当量(g) |

列位置は固定値でハードコードせず、12行目の成分識別子から解決する。
文科省が列を追加・並び替えた場合でも壊れないようにするためで、
識別子が見つからなければスクリプトはエラーで停止する。

## 変換スクリプト

`tools/build_food_database.py`(Python 3 / openpyxl)

### 入出力

- 入力: `tools/cache/mext_seibun.xlsx`。存在しなければ上記URLから取得して同パスに保存する。
  キャッシュ用ディレクトリなので `.gitignore` に追加し、xlsx自体はリポジトリに含めない。
- 出力1: `data/mext-foods.json` — アプリが読む(約300KB)
- 出力2: `docs/成分表/01_穀類.md` 〜 `18_調理済み流通食品類.md` — 人が読む

### 値のパース規則

成分表の数値セルには測定状況を示す記号が混在する。以下の規則で数値化する。

| 元の値 | 変換後 | 理由 |
|---|---|---|
| `123`, `12.3` | そのまま | 通常の測定値 |
| `(12.3)` | `12.3` | 推計値。値としては利用できる |
| `Tr` | `0` | 微量(最小記載量の1/10以上5/10未満)。栄養計算上は0として扱う |
| `-` | `0` | 未測定。0として扱い、計算を止めない |
| `*` | 無視 | 「この列を採用」の印であり数値ではない |
| 空欄 | `0` | 未測定と同様 |

`-` と空欄を0にすることで、未測定の成分が実際より少なく見積もられる。
本アプリは自分用の概算把握が目的であり、計算が破綻するよりは0で継続するほうが実用的と判断した。

### 糖質の算出

```
糖質 = 炭水化物(CHOCDF-) − 食物繊維総量(FIB-)
```

市販食品の栄養成分表示と同じ定義に揃える。食物繊維が未測定(`-`)の品目では
減算せず炭水化物をそのまま採用する。減算結果が負になった場合は0にクランプする。

算出値は小数第1位に丸める。

### 食品名の正規化

成分表の食品名は全角スペース(U+3000)で区切られている(例:
`こめ　[水稲めし]　精白米　うるち米`)。全角スペースを半角スペースに置換し、
連続する空白を1つにまとめ、前後の空白を除去する。

### 出力JSONの形式

```json
[
  {
    "code": "01088",
    "group": "穀類",
    "name": "こめ [水稲めし] 精白米 うるち米",
    "per100g": { "kcal": 156, "protein": 2.5, "fat": 0.3, "carb": 35.6, "salt": 0 }
  }
]
```

`carb` は上記の定義による糖質である(炭水化物ではない)。
アプリ内の既存フィールド名 `carb` と揃えるためこの名前を使う。

### 出力Markdownの形式

食品群ごとに1ファイル。Obsidianで開いたときに表として読め、
Ctrl+Fや全文検索で品目を探せることを目的とする。

```markdown
# 1 穀類

出典: 日本食品標準成分表(八訂)増補2023年(文部科学省)
生成日: 2026-08-08 / 品目数: 205

すべて可食部100gあたりの値。糖質は「炭水化物 − 食物繊維総量」で算出。

| 食品番号 | 食品名 | kcal | たんぱく質 | 脂質 | 糖質 | 食物繊維 | 炭水化物 | 食塩相当量 |
|---|---|---|---|---|---|---|---|---|
| 01001 | アマランサス 玄穀 | 343 | 12.7 | 6.0 | 57.5 | 7.4 | 64.9 | 0 |
```

食物繊維と炭水化物はJSONには含めないが、Markdownには載せる。
人が値の妥当性を確認する際に、糖質がどう算出されたか追えるようにするためである。

### 実行時の検証

スクリプトは出力後に以下を検証し、いずれかに該当したら警告を標準エラーに出す。

- 品目数が2,000件未満(パース位置のずれを検知するため)
- `kcal` が0の品目が全体の10%を超える
- `kcal` が1,000を超える品目(油脂類は900前後が上限)
- 糖質が負になりクランプされた品目の件数

## アプリ側の変更

### データモデルの変更

`foods` ストアに `mextCode` を追加する(成分表由来の品目のみ)。

```
foods (食品マスタ)
  - id
  - name           ユーザーが編集した表示名(例「白米」)
  - category
  - per100g: { kcal, protein, fat, carb, salt }
  - source: "custom"     ※成分表由来・手入力を問わず custom
  - mextCode: "01088"    ※成分表由来の場合のみ。出典の記録用
```

`source` を成分表由来でも `custom` とするのは、後述のマイグレーションが
`source === "mext"` を削除対象の目印に使うためである。新しく登録した品目が
将来のマイグレーションで巻き添えになることを避ける。

### マイグレーション(js/db.js)

- `DB_VERSION` を 1 から 2 に上げる
- `onupgradeneeded` で、旧バージョンからの更新時に `foods` ストアを走査し、
  `source === "mext"` のレコードをすべて削除する
- `seedFoodsIfEmpty` を削除する
- `data/foods.json` を削除する

削除された食品を参照していた既存の食事記録は、`js/render.js:51` の既存処理により
品目名が「(削除済み食品)」と表示される。栄養価は記録側にキャッシュ済みのため、
ダッシュボードの合計値と進捗バーは影響を受けない。

### 成分表の読み込み(js/mextTable.js・新規)

```
loadMextTable(): Promise<MextFood[]>
  data/mext-foods.json を fetch する。2回目以降はメモリ上のキャッシュを返す。
  食品管理画面を開いたときに初めて呼ばれる(起動時には読まない)。

searchMextFoods(table, query, limit = 50): MextFood[]
  食品名の部分一致で検索する。空クエリでは空配列を返す。
  前方一致する品目を先に、それ以外を後に並べ、limit件で打ち切る。
```

約300KBのJSONを起動時に読むとダッシュボードの初期表示が遅くなるため、遅延読み込みとする。
前方一致を優先するのは、「白米」で検索したとき名前の途中に「白米」を含む品目より
先頭が一致する品目を上に出したいためである。

照合は既存の `js/foodSearch.js` の `searchFoods` と同じく、`toLowerCase()` した
単純な部分一致とする。ひらがな・カタカナ・漢字の相互変換や読み仮名検索は行わない。
成分表の食品名は「こめ」「あわ」のようにひらがな主体のものと「精白米」のように
漢字を含むものが混在するため、目的の品目に辿り着けない場合はユーザーが表記を変えて
再検索する運用とする(読み仮名データを持たない成分表の制約であり、
別途よみがな辞書を用意しない限り解決しないため、今回のスコープ外とする)。

`searchFoods` と別関数にするのは、`searchMextFoods` が前方一致優先の並べ替えと
件数上限を持つためである。登録済み食品の検索は候補が数十件程度で全件表示してよく、
この2つは要件が異なるので統合しない。

### 食品管理画面(js/foodForm.js)

画面上部に成分表の検索セクションを追加する。既存の登録フォームと一覧はその下に残す。

```
┌─ 成分表から探す ────────────────┐
│ [検索ボックス]                          │
│ ・こめ [水稲めし] 精白米 うるち米  穀類 │
│ ・こめ [水稲めし] 玄米            穀類 │
└────────────────────────────┘
┌─ 食品の登録・編集 ──────────────┐
│ 食品名 [白米                    ]        │
│ カロリー [156] たんぱく質 [2.5] ...     │
│ [保存] [クリア]                          │
└────────────────────────────┘
┌─ 登録済みの食品 ────────────────┐
```

候補をクリックすると、その品目の名称と栄養値が登録フォームに流し込まれ、
食品名の入力欄にフォーカスが移り全選択された状態になる。
長い正式名称をすぐに短い名前へ打ち替えられるようにするためである。

`mextCode` は隠しフィールドとして保持し、保存時に一緒に書き込む。
フォームを手動でクリアするか、名前以外の栄養値をユーザーが書き換えた場合も
`mextCode` は保持する(どの品目を元にしたかの記録として意味があるため)。

初回の検索時に `loadMextTable()` が走るため、読み込み中は候補リストに
「成分表を読み込んでいます...」を表示し、失敗時は「成分表の読み込みに失敗しました」を表示する。

### 食事記録モーダル(js/mealForm.js)

登録済み食品が0件のとき、食品名の入力前から
「まだ食品が登録されていません。食品管理から登録してください。」を表示する。

白紙状態で食事を記録しようとした利用者が、何を入力しても候補が出ない状態で
行き止まりになることを防ぐ。既存の「見つかりません→新しい食品として登録する」導線は
そのまま残す。

### Service Worker(sw.js)

- `ASSETS` から `./data/foods.json` を削除し、`./data/mext-foods.json` と
  `./js/mextTable.js` を追加する
- `CACHE_NAME` を `calorie-app-v2` から `calorie-app-v3` に更新する

## 主要な操作フロー

**成分表から食品を登録する**

1. 下部ナビの「食品」をタップ → 食品管理画面(初回は一覧が空)
2. 「成分表から探す」に「精白米」と入力(表記どおりに検索する必要がある)
3. 候補「こめ [水稲めし] 精白米 うるち米」をタップ
4. 登録フォームに名称と栄養値(156kcal / 2.5 / 0.3 / 35.6 / 0)が入り、名前が全選択される
5. 「白米」と打ち替えて「保存」→ 登録済み一覧に「白米」が追加される
6. 以降、食事記録モーダルで「白」と入力すると候補に「白米」が出る

## エラーハンドリング

| 状況 | 挙動 |
|---|---|
| `mext-foods.json` の取得失敗 | 候補欄に「成分表の読み込みに失敗しました」を表示。手入力での登録は引き続き可能 |
| 成分表の検索が0件 | 「該当する品目がありません」を表示。手入力フォームはそのまま使える |
| 登録食品0件で食事記録を開く | モーダル上部に食品管理への案内を表示 |
| 変換スクリプトで成分識別子が見つからない | エラー終了し、出力ファイルを書き換えない |

## テスト方針

既存方針(純粋ロジックのみ軽量テスト、UI操作は手動確認)を踏襲する。

**Python側**(`tools/test_build_food_database.py`、`python -m unittest` で実行)

- 値パース: `123` / `12.3` / `(12.3)` / `Tr` / `-` / `*` / 空欄 / 不正文字列
- 糖質算出: 通常ケース、食物繊維が未測定のケース、負値のクランプ
- 食品名正規化: 全角スペース、連続空白、前後の空白

**JavaScript側**(`tests/` 配下、`node --test` で実行)

- `searchMextFoods`: 空クエリ、部分一致、前方一致の優先、limitでの打ち切り、該当なし

**手動確認**

- 白紙状態からの登録フロー(上記「主要な操作フロー」の1〜6)
- 既存の食事記録が「(削除済み食品)」表示になり、合計値は変わらないこと
- 名前を編集せずに保存した場合も正しく登録されること
- オフライン(機内モード)で成分表の検索ができること(Service Workerのキャッシュ確認)

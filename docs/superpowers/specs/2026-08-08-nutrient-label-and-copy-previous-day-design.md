# 栄養素表記の変更と「前日の内容を転記する」機能 設計書

日付: 2026-08-08

## 背景・目的

1. 食事記録の表示(ダッシュボードの品目行、食事記録モーダルのプレビュー行)で、タンパク質・脂質・糖質が`P`/`F`/`C`という略記で表示されており分かりにくい。フルの日本語表記に変更する。
2. 毎日同じような食事を記録する手間を減らすため、前日の記録をまとめて当日にコピーする機能を追加する。

## スコープ

### 対象

- `js/render.js`: `renderMealSection`内の品目行の略記表示。
- `js/mealForm.js`: プレビュー行の略記表示。
- `index.html`: 間食セクションの下に「前日の内容を転記する」ボタンを追加。
- `js/app.js`: 転記ボタンの挙動を実装。
- `js/db.js`: 変更なし(既存の`getMealsByDate`/`addMeal`をそのまま利用)。

### 対象外

- `js/foodForm.js`: 既にフル表記(「タンパク質(g/100g)」等)のため変更なし。

## 設計

### 1. 栄養素表記の変更

- `js/render.js`の`renderMealSection`内、品目行(`meal-item-row2`)の表示を
  `P${meal.protein}g F${meal.fat}g C${meal.carb}g` → `タンパク質${meal.protein}g 脂質${meal.fat}g 糖質${meal.carb}g` に変更する。
- `js/mealForm.js`のプレビュー行(`updatePreview`内)の表示を同様に
  `P${nutrients.protein}g F${nutrients.fat}g C${nutrients.carb}g` → `タンパク質${nutrients.protein}g 脂質${nutrients.fat}g 糖質${nutrients.carb}g` に変更する。
- `.meal-item-row2`は既に`flex-wrap: wrap`が指定されているため、テキストが長くなっても折り返され、CSS変更は不要。

### 2. 「前日の内容を転記する」機能

- **配置**: `index.html`の`#meal-snack`セクションの直後(ダッシュボード最下部)に、常時表示のボタン`#copy-previous-day`を追加する。4区分の記録全体に対する一括操作のため、特定の区分に属さない独立したボタンとして配置する。
- **対象データ**: 前日(`state.date`の1日前)の`meals`全件(朝食・昼食・夕食・間食すべて)。
- **挙動**:
  1. ボタン押下時、`getMealsByDate(db, 前日の日付)`で前日の記録を取得する。
  2. 0件の場合は「前日の記録がありません」という旨をその場に表示し(alertまたは簡易メッセージ)、処理を終了する。
  3. 1件以上ある場合は`confirm()`で「前日(YYYY-MM-DD)の記録◯件を(表示中の日付)に追加しますか?」と確認する(`foodForm.js`の削除確認と同じ`confirm()`パターンを踏襲)。転記先は常に`state.date`(現在ダッシュボードで表示中の日付)であり、過去の日付を閲覧中でも「今日」ではなくその表示中の日付に転記されるため、確認文言にも表示中の日付を明示する。
  4. 確認後、各レコードについて`id`と`date`を除いた内容(`mealType` / `foodId` / `freeText` / `amountGrams` / `kcal` / `protein` / `fat` / `carb` / `salt`)をそのまま引き継ぎ、`date`を当日の日付に差し替えて`addMeal`で新規レコードとして複製登録する。栄養価は前日記録時点の計算済みキャッシュ値をそのまま使う(食品マスタの再計算は行わない。食品データが編集されていても、転記元の記録内容を忠実に再現するため)。
  5. 全件登録後、`refreshDashboard()`でダッシュボードを再描画する。
- **重複について**: 当日に既に同じ内容の記録があっても検知・マージはしない(単純追加)。確認ダイアログで実行有無をユーザーが判断する。誤って重複させた場合は既存の削除機能で個別に削除できる。
- **参照先食品が削除されている場合**: `foodId`が指す食品が既に削除されていても、レコード自体はキャッシュ済みの栄養価を保持しているため問題なくコピーできる。表示は既存の`(削除済み食品)`フォールバックに従う。

## エラーハンドリング・データ整合性

- IndexedDBへの書き込みは1件ずつ`addMeal`を呼び出す(トランザクションを跨ぐ複数呼び出し)。件数は最大でも1日分(4区分)のため、パフォーマンス上の懸念はない。
- 前日の記録取得・登録中に例外が発生した場合は、既存の起動時エラーバナーと同様の簡易な扱い(現状のコードベースには汎用エラーハンドリング機構がないため、追加のtry/catchで最小限のalert表示に留める)。

## テスト方針

既存方針(手動確認中心)を踏襲する。実ブラウザで以下を確認する:

- 前日に記録がある状態でボタンを押すと確認ダイアログが出て、OKで当日に同内容が追加されること
- 前日に記録が無い状態でボタンを押すと「前日の記録がありません」旨が表示され、何も追加されないこと
- 確認ダイアログでキャンセルした場合、何も追加されないこと
- 転記後、ダッシュボードの合計値・進捗バーが正しく更新されること
- 品目行・プレビュー行が「タンパク質/脂質/糖質」のフル表記になっていること、かつ狭い画面幅でも折り返されて表示が崩れないこと

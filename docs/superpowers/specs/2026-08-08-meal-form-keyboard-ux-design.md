# 食事記録モーダルのキーボードUX改善 設計書

日付: 2026-08-08

## 背景・目的

食事記録フォーム(`js/mealForm.js`)で、食品名の候補表示と保存操作がマウス/タップ操作前提になっており、キーボードだけでの入力が使いにくい。以下2点を改善する。

1. 食品名の候補が「入力欄の下に押し出すインラインリスト」として表示され、量(g)欄を押し下げてしまう。プルダウン(オーバーレイ)表示に変更する。
2. 量(g)欄でTabキーを押すと「キャンセル」ボタンに先に到達してしまい、「保存」ボタンに直接到達できない。これは食品登録画面(`js/foodForm.js`)の「保存が先・クリアが後」という並び順とも逆になっている。

## 現状分析(実機確認済み)

- `#meal-food-results`は通常の`<ul>`としてDOMフロー内に配置されており、候補が表示されると後続の「量(g)」欄が下に押し出される。オーバーレイではない。
- `.modal-actions`内のボタン順序は「キャンセル→保存」。量(g)欄からTabを押すと`meal-cancel`にフォーカスが移動することを確認済み。
- `js/foodForm.js`は`<form>`要素+`type="submit"`ボタンを使っており、ボタン順序は「保存→クリア」。Enterキーでの送信にも対応している。
- `js/mealForm.js`は`<div>`ベースの手動イベント配線で、`<form>`要素を使っていない。

## スコープ

### 対象

- `js/mealForm.js`: 食品名入力欄のコンボボックス化(オーバーレイ+キーボード操作)、ボタン順序の変更、`<form>`化。
- `style.css`: オーバーレイ用のスタイル、ハイライト状態のスタイル。

### 対象外

- `js/foodForm.js`・設定画面: 変更なし(既に望ましい並び順・`<form>`化が済んでいるため)。
- `js/foodSearch.js`の検索ロジック自体: 変更なし。

## 設計

### 1. 食品名候補のプルダウン化(コンボボックス化)

- 食品名`<input>`をラップする相対配置コンテナ(例: `.food-combobox`)を追加し、`#meal-food-results`を`position: absolute`のオーバーレイとして配置する(`box-shadow`で浮いている見た目にする)。後続の「量(g)」欄を押し下げないようにする。
- キーボード操作:
  - `ArrowDown` / `ArrowUp`: 候補リスト内のハイライト位置を1つ進める/戻す(循環はしない。末尾/先頭で止まる)。
  - `Enter`: ハイライト中の候補があればそれを選択して確定し、リストを閉じる。ハイライトが無い状態(まだ矢印キー未操作)でのEnterは何もしない(誤操作防止)。
  - `Escape`: リストを閉じる(入力テキストはクリアしない)。
  - 上記いずれのキー処理でも、食品名入力欄内では`Enter`によるフォーム送信を`preventDefault`し、量欄に到達する前に誤って保存されないようにする。
- ハイライト中の候補には`.is-active`クラスを付与し、背景色で視覚的に区別する。
- マウス/タップでのクリック選択は現状の挙動を維持する。
- 候補リスト外(モーダル内外問わず)をクリック/タップした場合はリストを閉じる。

### 2. Tabキー・Enterキーでの保存対応

- モーダルのマークアップを`<div class="modal-actions">`から`<form>`ベースに変更し、`js/foodForm.js`と同様に`保存/更新`ボタンを`type="submit"`にする。
- ボタン順序を「保存(または更新)→キャンセル」に変更する(`js/foodForm.js`と統一)。これにより量(g)欄からTabを押すと直接「保存」ボタンにフォーカスが移動する。
- 量(g)欄の`keydown`イベントで`Enter`を検知し、`saveBtn.disabled`をガードした上で`form.requestSubmit()`を明示的に呼び出すことでフォームを送信し保存する(食品選択済み・量が有効な場合)。これによりクリックでの保存(`type="submit"`ボタン経由)とEnterキーでの保存が同じ制約検証・同じsubmitイベント経由の保存パスを通り、挙動が一致する。保存ボタンが`disabled`の間はこのガードによりEnterでの送信も発生しない。
- キャンセルボタンは`type="button"`のまま(送信に関与しない)。

## エラーハンドリング・データ整合性

- 既存の「見つかりません→新規登録」導線(`#meal-no-result` / `#meal-register-new`)は変更しない。
- 量(g)のバリデーション(0以下で保存ボタン無効化)は現状のロジックを維持する。
- `foodSearch.js`の検索結果自体のロジックは変更しないため、既存の単体テスト(`tests/foodSearch.test.js`)への影響はない。

## テスト方針

既存方針(手動確認中心)を踏襲する。実ブラウザで以下を確認する:

- 候補プルダウンが量(g)欄を押し下げずにオーバーレイ表示されること
- `↑`/`↓`でハイライトが移動し、`Enter`で確定できること
- `Escape`で候補が閉じ、入力テキストは保持されること
- 候補リスト外クリックで候補が閉じること
- 量(g)欄から`Tab`を押すと「保存」ボタンに直接到達すること
- 量(g)欄で`Enter`を押すと保存できること(食品未選択・量未入力時は保存されないこと)
- 既存の新規登録・編集フロー、キャンセル動作が壊れていないこと

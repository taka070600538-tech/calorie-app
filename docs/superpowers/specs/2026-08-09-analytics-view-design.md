# 分析タブ設計

記録の経時的な推移を表と折れ線グラフで振り返り、期間平均・カロリー収支・体脂肪換算を確認できる「分析」タブを追加する。

## 背景と前提

現在のアプリは1日単位の記録と目標比しか見られない。数週間単位で自分の食事がどう推移したかを振り返る手段がない。

カロリー収支を出すには消費カロリーが要るが、アプリは摂取側のデータしか持っていない。`goals.kcal` は「目標摂取量」であって消費量ではないため、これを流用すると「収支」ではなく「目標との差」になってしまう。そこで消費カロリーを設定項目として新設する。

### 確定した定義

| 項目 | 定義 |
| --- | --- |
| 消費カロリー | 設定画面で手入力する1日あたりの固定値。日ごとの記録はしない |
| カロリー収支 | 摂取 − 消費。プラスが余剰（体脂肪が増える向き）、マイナスが不足 |
| 体脂肪換算 | 収支 kcal ÷ 7200 = kg。体脂肪組織は約80%がトリグリセリドのため 9 kcal/g × 0.8 ≈ 7.2 kcal/g |
| 無記録日 | 「記録し忘れ」とみなし、平均の分母にも収支の日数にも含めない |

## アーキテクチャ

計算・描画・DOM を3つのモジュールに分ける。既存の `nutrition.js` / `mextTable.js` と同じく、純粋関数を切り出してテストを当てる流儀に揃える。

| ファイル | 責務 | テスト |
| --- | --- | --- |
| `js/analytics.js` | 日別集約・期間平均・収支・体脂肪換算。純粋関数のみ | `tests/analytics.test.js` |
| `js/lineChart.js` | データ → SVG 文字列。純粋関数のみ | `tests/lineChart.test.js` |
| `js/dateUtils.js` | 日付の書式・加減算・プリセット期間の算出 | `tests/dateUtils.test.js` |
| `js/analyticsView.js` | DOM 描画とイベント処理 | 手動確認 |

SVG 生成を独立させる理由は、座標変換（値 → y 座標、目標線の位置、無記録日をまたぐ線）という最もバグりやすい部分に直接テストを当てられるため。

グラフは `<canvas>` ではなくインライン SVG の文字列生成とする。既存コードが `innerHTML` へのテンプレート文字列生成で統一されており、かつ SVG なら生成部を純粋関数にできる。

## データ取得

`js/db.js` に1関数を追加する。

```js
getMealsByDateRange(db, from, to)  // by_date インデックス + IDBKeyRange.bound(from, to)
```

`date` は `'YYYY-MM-DD'` 形式で辞書順が時系列順と一致するため、範囲クエリがそのまま成立する。期間全体を1トランザクションで取得し、日別集約はメモリ上で行う。日ごとにクエリを回すことはしない。

## 消費カロリーの保存

`goals` ストアの `default` レコードに `expenditureKcal` を追加する。IndexedDB のオブジェクトストアはスキーマレスなので **DB_VERSION は 2 のまま**でよく、マイグレーションは不要。

`db.js` の `DEFAULT_GOALS` に `expenditureKcal: 2000` を加えることで、既存レコードにフィールドが無い場合も `getGoals` がこの値でフォールバックする。

デフォルト値 2000 は根拠のある値ではないため、そのまま使うと体脂肪換算が黙って的外れな数字になる。これを防ぐため、分析画面のサマリーに「消費カロリー 2,000 kcal/日 として計算」を**常に**表示し、どの前提で出た数字かが必ず見えるようにする。

## 計算ロジック（`js/analytics.js`）

```js
groupMealsByDate(meals)
// → [{ date, kcal, protein, fat, carb, salt }] を日付昇順で返す。
//   記録のある日だけが要素になるため、無記録日の除外が自然に成立する。
//   栄養値の合算には既存の sumNutrients を再利用する。

calcPeriodStats(dailyTotals, expenditureKcal)
// → {
//     dayCount,               記録のあった日数
//     averages: { kcal, protein, fat, carb, salt },
//     totalIntakeKcal,
//     totalExpenditureKcal,   expenditureKcal × dayCount
//     energyBalanceKcal,      totalIntakeKcal − totalExpenditureKcal
//     bodyFatKg,              energyBalanceKcal ÷ 7200
//   }
```

`meals` レコードは記録時点の栄養値を実体として持つため、食品マスタを再参照する必要はない。

### 丸めと符号

- 平均カロリー・収支 kcal・摂取合計・消費合計は整数
- 平均のタンパク質・脂質・糖質・塩分は小数1桁
- 体脂肪換算は小数2桁
- 収支と体脂肪換算は符号付きで表示する（`+2,400 kcal` / `体脂肪 +0.33 kg`）。丸めた結果が 0 のときは符号を付けず `0 kcal` / `0.00 kg` とする

### 日ごとの収支

表の「収支」列は `その日の摂取kcal − expenditureKcal`。期間合計はこの日別収支の総和であり、記録のある日しか含まれない。

### 境界条件

`dayCount === 0` のとき平均が 0 除算になる。`calcPeriodStats` は集計値をすべて 0 で返し、画面側はこれを「この期間に記録がありません」の分岐に使う。

## 日付ユーティリティ（`js/dateUtils.js`）

`app.js` にローカル定義されている `formatDate` / `shiftDate` をこのファイルへ移し、`app.js` と `analyticsView.js` の双方が import する。定義の重複を避けるための移動であり、振る舞いは変えない。

```js
formatDate(dateObj)                 // → 'YYYY-MM-DD'
shiftDate(dateStr, days)            // → 'YYYY-MM-DD'
calcPresetRange(todayStr, days)     // → { from, to }
```

`calcPresetRange` は終了日を今日、開始日を `days - 1` 日前とする。「直近7日」は今日を含めて7日間を意味する。

## グラフ（`js/lineChart.js`）

```js
buildLineChartSvg(points, { goalValue, unit, fromDate, toDate })  // → SVG 文字列
// points: [{ date: 'YYYY-MM-DD', value: number }] 日付昇順・記録のある日のみ
```

DOM も IndexedDB も触らず、文字列を返すだけ。`analyticsView.js` がこれを `innerHTML` に流し込む。

### x 軸は経過日数でマッピングする

点を等間隔に並べると無記録日が詰まって時間軸が歪む。`fromDate` からの経過日数をもとに実際の日付位置へ配置する。結果として無記録日は線が長く伸びたギャップになり、「線を切らずに前後をつなぐ」という方針がそのまま絵になる。

### y 軸は 0 を下端に固定する

上端は「データ最大値と目標値の大きい方」を切りのいい値へ切り上げた値とする。データの min–max に合わせて拡大すると、1,900〜2,100 kcal の揺れが画面いっぱいの乱高下に見えて実態を誤読する。

切り上げの刻みは `10^floor(log10(v)) / 2` と定める。2,100 なら刻み 500 で上端 2,500、65 なら刻み 5 で上端 65、7.3 なら刻み 0.5 で上端 7.5。`v` が 0 のときは上端を 1 とする。

### 描画要素

- 折れ線1本（`<polyline>`）と各データ点の小さな丸
- 目標値の水平破線とラベル。選択中の栄養素に対応する `goals` の値を使う
- x 軸ラベルは開始日・終了日の2つのみ（`8/1` `8/9` 形式）。スマホ幅で日付を並べても潰れる
- y 軸ラベルは上端値と 0

### レスポンシブ

`viewBox` と `width="100%"` で行う。固定 px は指定せず、SVG 内部の座標系は固定のまま表示のみ伸縮させる。

### 境界条件

| 状況 | 挙動 |
| --- | --- |
| 点が1つだけ | 折れ線を引かず、点と目標線のみ描画する（経過日数の除算が 0 割になるため） |
| 点が0個 | この関数を呼ばない。画面側が「この期間に記録がありません」を表示する |
| 全値が 0 かつ目標値も 0 | y 軸上端に最小値 1 を入れ、全点が下端に重なるのを防ぐ |

## 画面（`js/analyticsView.js`）

### 構成（上から）

1. **期間セレクタ** — `[直近7日] [直近30日] [直近90日]` のプリセットボタンと、開始日・終了日の `<input type="date">`。初期表示は直近7日。プリセットを押すと2つの `<input type="date">` の値も同期して書き換わり、いま何日から何日を見ているかが常に読み取れる状態にする
2. **サマリー** — 集計対象の明示（「9日分の記録（2026-08-01 〜 2026-08-09）」）、栄養素5つの平均と目標比 %（既存の `calcProgress` を使う）、摂取合計・消費合計・収支・体脂肪換算、末尾に「消費カロリー 2,000 kcal/日 として計算」の注記
3. **グラフ** — `[カロリー][タンパク質][脂質][糖質][塩分]` のタブと SVG
4. **表** — 日付／kcal／タンパク質／脂質／糖質／塩分／収支 の7列。`groupMealsByDate` は日付昇順で返すため、表示時に反転して**日付の新しい順**に並べる。スマホ幅に収まらないため表だけ `overflow-x: auto` で横スクロールさせる

### 再計算の境界

期間が変わったときだけ IndexedDB を読み直す。栄養素タブの切り替えは取得済みデータからグラフを描き直すだけで、再取得はしない。

状態（`from` / `to` / `metric` / `dailyTotals`）は `analyticsView.js` のローカルに閉じ、`app.js` の `state` には持ち込まない。

### エラーと異常系

| 状況 | 表示 |
| --- | --- |
| 開始日 > 終了日 | 「開始日が終了日より後です」。集計もグラフも出さない |
| 期間内に記録が0件 | 「この期間に記録がありません」 |
| 読み込み失敗 | 「記録の読み込みに失敗しました」。既存の `copyPreviousDay` と同様に `try/catch` で握って画面に出す |

## 既存ファイルへの変更

| ファイル | 変更内容 |
| --- | --- |
| `index.html` | `<main id="view-analytics" class="view hidden">` を追加。ナビを「今日の記録 / 分析 / 食品管理 / 設定」の4つにする |
| `js/app.js` | ナビに `analytics` の分岐を追加。`formatDate` / `shiftDate` のローカル定義を削除し `dateUtils.js` から import |
| `js/db.js` | `getMealsByDateRange` を追加。`DEFAULT_GOALS` に `expenditureKcal: 2000` |
| `js/settings.js` | 「1日の消費カロリー(kcal)」の入力を追加。見出しを「栄養目標」と「消費カロリー」の2ブロックに分け、保存は既存の `saveGoals` にまとめる。`newGoals` はフィールドを明示列挙しているため追加が必要 |
| `sw.js` | `ASSETS` に `js/analytics.js` `js/lineChart.js` `js/dateUtils.js` `js/analyticsView.js` を追加。`CACHE_NAME` を `calorie-app-v4` から `calorie-app-v5` へ |
| `style.css` | 期間セレクタ・サマリー・タブ・表・SVG コンテナのスタイル |

`.nav-btn` は `flex: 1` なので4つでも等分され、スマホ幅でも収まる。

`sw.js` は cache-first のため、`CACHE_NAME` を上げ忘れると新規ファイルが 404 になる。

## テスト

`node --test tests/*.test.js` で実行する。

| ファイル | 検証内容 |
| --- | --- |
| `tests/analytics.test.js` | 日別集約が日付昇順になること、無記録日が要素にならないこと、平均・収支・体脂肪換算の値、`dayCount === 0` のとき 0 除算せず 0 を返すこと |
| `tests/lineChart.test.js` | 両端の点が描画領域の左右端にあること、値が目標値と等しい点が目標線と同じ y 座標になること、無記録日を挟んだ2点の x 間隔が連続する2点の2倍になること、点が1つのとき `polyline` が出ないこと、y 軸上端の切り上げ規則（2,100→2,500 / 65→65 / 7.3→7.5 / 0→1） |
| `tests/dateUtils.test.js` | `calcPresetRange` が今日を含む N 日になること、月またぎ、うるう年 |

DOM を持つ `analyticsView.js` は既存の view ファイル同様、自動テストの対象外とし手動確認する。

## スコープ外

- 体重の記録と、それに基づく消費カロリーの自動算出
- 日ごとの消費カロリー入力
- 週単位・月単位への集約切り替え
- グラフへの複数栄養素の同時表示
- 分析結果のエクスポート
